# 客户服务日志与日常服务日志工时单位改造设计文档

## 一、背景与目标

### 1.1 背景

当前系统中存在三种服务日志：
- **项目服务日志**（`ProjectScheduleController`）：已完成工时单位改造，支持小时录入
- **客户服务日志**（`CustomerServiceController`）：仍使用天为单位
- **日常服务日志**（`WorkLogController`）：仍使用天为单位

为保持系统一致性，提升用户体验，需要对客户服务日志和日常服务日志进行工时单位改造。

### 1.2 目标

1. 将工时录入单位从「天」改为「小时」
2. 保持与项目服务日志相同的设计模式和校验逻辑
3. 确保历史数据兼容，不影响成本核算
4. 统一三张服务日志表的工时校验标准（每日 8 小时上限）

```java
private static final BigDecimal WORK_HOURS_PER_DAY = new BigDecimal("8");

private static final BigDecimal WORK_HOURS_THRESHOLD = new BigDecimal("8.02");
```

#### 2.2.3 工时校验方法

```java
private void validateWorkHoursLimit(String staffId, Date workDate,
                                    BigDecimal currentWorkHoursHour,
                                    BigDecimal originalWorkHoursHour) {
    // 1. 计算当日时间范围
    Date startTime = DateUtil.beginOfDay(workDate);
    Date endTime = DateUtil.endOfDay(workDate);

    // 2. 查询当日已填工时（单位：天），转换为小时
    BigDecimal existWorkHoursInDay = bizWorkHoursService.getTotalWorkHours(staffId, startTime, endTime);
    BigDecimal existWorkHoursInHour = existWorkHoursInDay.multiply(WORK_HOURS_PER_DAY);

    // 3. 计算当前记录在其他表中的工时
    BigDecimal otherRecordsHours = calculateOtherRecordsHours(staffId, startTime, endTime, workDate);

    // 4. 计算总工时（单位：小时）
    BigDecimal totalWorkHoursInHour = existWorkHoursInHour.add(currentWorkHoursHour);

    // 5. 编辑时需扣除原记录工时
    if (originalWorkHoursHour != null) {
        totalWorkHoursInHour = totalWorkHoursInHour.subtract(originalWorkHoursHour);
    }

    // 6. 工时超过限制（容忍精度误差）
    if (totalWorkHoursInHour.compareTo(WORK_HOURS_THRESHOLD) > 0) {
        BigDecimal remainHours = WORK_HOURS_PER_DAY.subtract(otherRecordsHours);
        throw new JeecgBootException(String.format(
            "日期：%s 填写工时累计超过8小时，剩余【%s】小时可填",
            DateUtil.formatDate(workDate),
            remainHours.setScale(1, RoundingMode.HALF_UP)
        ));
    }
}
```

##### 新增校验方法

```java
/**
 * 校验工时是否超过每日限制
 *
 * @param staffId 员工ID
 * @param workDate 工作日期
 * @param currentWorkHoursHour 当前记录工时（小时）
 * @param originalWorkHoursHour 原记录工时（小时），编辑时传入，新增时为null
 */
private void validateWorkHoursLimit(String staffId, Date workDate,
                                    BigDecimal currentWorkHoursHour,
                                    BigDecimal originalWorkHoursHour) {
    if (currentWorkHoursHour == null || currentWorkHoursHour.compareTo(BigDecimal.ZERO) <= 0) {
        return;
    }

    // 计算当日时间范围
    Date startTime = DateUtil.beginOfDay(workDate);
    Date endTime = DateUtil.endOfDay(workDate);

    // 查询当日已填工时（单位：天），转换为小时统一计算
    BigDecimal existWorkHoursInDay = bizWorkHoursService.getTotalWorkHours(staffId, startTime, endTime);
    BigDecimal existWorkHoursInHour = existWorkHoursInDay.multiply(WORK_HOURS_PER_DAY);

    // 计算总工时（单位：小时）
    BigDecimal totalWorkHoursInHour = existWorkHoursInHour.add(currentWorkHoursHour);

    // 编辑时需扣除原记录工时
    if (originalWorkHoursHour != null) {
        totalWorkHoursInHour = totalWorkHoursInHour.subtract(originalWorkHoursHour);
    }

    // 工时超过限制（容忍精度误差）
    if (totalWorkHoursInHour.compareTo(WORK_HOURS_THRESHOLD) > 0) {
        // 计算其他记录工时
        BigDecimal otherRecordsHours = existWorkHoursInHour;
        if (originalWorkHoursHour != null) {
            otherRecordsHours = otherRecordsHours.subtract(originalWorkHoursHour);
        }
        BigDecimal remainHours = WORK_HOURS_PER_DAY.subtract(otherRecordsHours);

        throw new JeecgBootException(String.format(
            "日期：%s 填写工时累计超过8小时，剩余【%s】小时可填",
            DateUtil.formatDate(workDate),
            remainHours.setScale(1, RoundingMode.HALF_UP)
        ));
    }
}
```

## 四、工时统计服务影响分析

### 4.1 IBizWorkHoursService 分析

**文件路径**：`org.jeecg.modules.mzx.service.IBizWorkHoursService`

**核心方法**：`getTotalWorkHours(String staffId, Date startTime, Date endTime)`

该方法汇总三张表的 `work_hours` 字段（单位：天）：

```sql
SELECT
    (SELECT IFNULL(SUM(work_hours), 0) FROM biz_customer_service_log ...) +
    (SELECT IFNULL(SUM(work_hours), 0) FROM biz_project_schedule_log ...) +
    (SELECT IFNULL(SUM(work_hours), 0) FROM biz_work_log ...)
```

### 4.2 兼容性说明

| 场景 | 处理方式 | 影响 |
|------|---------|------|
| **历史数据** | 已迁移 `work_hours_hour = work_hours * 8` | 兼容 |
| **新数据** | 双写 `work_hours = work_hours_hour / 8` | 兼容 |
| **统计查询** | 仍使用 `work_hours` 字段 | 无需修改 |

**结论**：`IBizWorkHoursService.getTotalWorkHours()` 方法无需修改，统计逻辑保持不变。

## 七、风险与注意事项

### 7.1 数据迁移风险

- **风险**：历史数据迁移可能失败或数据丢失
- **缓解措施**：
  1. 执行前备份相关表
  2. 在测试环境验证迁移脚本
  3. 执行后验证数据一致性

### 7.2 精度问题

- **风险**：浮点数计算精度误差
- **缓解措施**：
  1. 使用 `BigDecimal` 进行计算
  2. 设置合理的校验阈值（8.02 小时）
  3. 保留 3 位小数精度

### 7.3 并发问题

- **风险**：多人同时填写同一员工工时可能超额
- **缓解措施**：数据库层面添加乐观锁或分布式锁（当前实现未涉及，建议后续优化）

### 7.4 前后端协调

- **风险**：前端未同步修改导致接口调用失败
- **缓解措施**：
  1. 与前端团队充分沟通
  2. 保持向后兼容（同时支持 `workHours` 和 `workHoursHour`）
  3. 分阶段上线
