# 项目成本看板新增加班时长统计设计

## 一、需求背景

### 1.1 需求描述
在项目成本看板（`/project/cost/calculate/list`）新增"加班时长"列，统计每个项目的加班总时长。

### 1.2 业务规则
- **数据时效**：T+1，即今日数据明日统计（通过定时任务触发）
- **统计条件**：只统计已确认（`confirm_status = 1`）的加班记录
- **数据来源**：`biz_overtime_record` 表，通过 `project_id` 关联项目
- **触发机制**：加班记录新增、编辑、确认时写入 `biz_project_change_detail` 变更记录表，定时任务根据变更记录判断是否需要重新计算

### 1.3 现有加班记录表结构
```
biz_overtime_record
├── id              -- 主键
├── project_id      -- 关联项目ID
├── staff_id        -- 员工ID
├── overtime_date   -- 加班日期
├── overtime_hours  -- 加班时长（小时，decimal(4,1)）
├── confirm_status  -- 确认状态（0:待确认, 1:已确认）
└── del_flag        -- 删除标记
```

## 二、技术方案

### 2.1 方案概述
采用与现有项目成本统计相同的技术架构：
1. 在 `biz_project_cost_calculate` 表新增 `overtime_hours` 字段
2. 在定时任务 `ProjectCostDayJob` 中增加加班时长统计逻辑
3. 加班记录操作时写入变更记录表，触发定时任务重新计算
4. 修改前端列表展示新增字段

### 2.2 数据流程
```
biz_overtime_record（加班记录新增/编辑/确认）
        │
        ▼
biz_project_change_detail（变更记录表，使用当前时间）
        │
        ▼
ProjectCostDayJob（定时任务判断是否有变动）
        │
        ▼
sumOvertimeHoursByProject（按项目统计已确认加班时长）
        │
        ▼
biz_project_cost_calculate.overtime_hours（项目成本看板）
```

## 五、统计逻辑说明

### 5.1 统计条件
- 只统计 `confirm_status = 1`（已确认）的加班记录
- 只统计 `del_flag = 0`（未删除）的加班记录
- **不限时间范围**，统计项目所有已确认的加班时长总和

### 5.2 变更触发机制

#### 触发时机
在 `BizOvertimeRecordService` 的以下操作中调用 `IBizProjectChangeDetailService#insertOrUpdateData`：
- `submitOvertime`：新增/编辑加班记录成功后
- `confirmOvertime`：确认加班记录成功后

#### 调用方式
使用**当前时间**触发变更，而不是加班日期：

```java
// 使用当前时间触发变更，因为可能编辑/确认历史数据
if (result && StringUtils.isNotBlank(projectId)) {
    projectChangeDetailService.insertOrUpdateData(projectId);
}
```

#### 设计原因
由于用户可能编辑或确认**上个月甚至更早**的加班记录，如果使用加班日期作为变更时间，则变更记录会写入历史月份。定时任务在当前月份执行时无法检测到这个变更，导致成本看板数据不会更新。

使用当前时间可以确保：
- 即使编辑历史数据，变更记录也会记录在当前月份
- 定时任务在当月执行时能检测到变更并重新计算

### 5.3 定时任务逻辑

在 `BizProjectCostCalculateService.initProjectCostCalculate` 方法中：

```java
// 1. 获取当月有变动的项目列表
List<String> projectIdList = projectCostDetailMapper.listMonitorCostProject(period);

// 2. 按项目汇总加班时长（不限时间范围）
List<OvertimeHoursModel> overtimeHoursModels = overtimeRecordService.sumOvertimeHoursByProject(projectIdList);

// 3. 构造项目成本核算数据，设置加班时长字段
projectList.forEach(project -> {
    BizProjectCostCalculate tempDate = structureProjectCostCalculate(project, projectCostModels, overtimeHoursModels);
    // ...
});
```

## 六、关键代码示例

### 6.1 BizOvertimeRecordMapper.xml

```xml
<!-- 按项目统计已确认的加班时长（不限时间范围） -->
<select id="sumOvertimeHoursByProject" resultType="org.jeecg.modules.mzx.model.OvertimeHoursModel">
    SELECT
        project_id AS projectId,
        IFNULL(SUM(overtime_hours), 0) AS overtimeHours
    FROM biz_overtime_record
    WHERE del_flag = 0
      AND confirm_status = 1
      AND project_id IN
      <foreach collection="projectIds" item="projectId" separator="," open="(" close=")">
          #{projectId}
      </foreach>
    GROUP BY project_id
</select>
```

### 6.2 BizOvertimeRecordService 变更触发

```java
@Override
public boolean submitOvertime(BizOvertimeRecord overtimeRecord) {
    // ... 校验和数据设置 ...
    
    if (isNew) {
        boolean result = this.save(overtimeRecord);
        // 记录项目变更（使用当前时间）
        if (result && StringUtils.isNotBlank(overtimeRecord.getProjectId())) {
            projectChangeDetailService.insertOrUpdateData(overtimeRecord.getProjectId());
        }
        return result;
    } else {
        boolean result = this.updateById(overtimeRecord);
        // 记录项目变更（使用当前时间）
        if (result && StringUtils.isNotBlank(overtimeRecord.getProjectId())) {
            projectChangeDetailService.insertOrUpdateData(overtimeRecord.getProjectId());
        }
        return result;
    }
}

@Override
public boolean confirmOvertime(String id, String confirmerId, String confirmerName) {

    }

}
```

## 七、验证方案

### 7.1 功能测试
1. 准备测试数据：创建项目、添加已确认的加班记录
2. 执行定时任务：`ProjectCostDayJob`
3. 查询项目成本看板列表，验证 `overtimeHours` 字段是否正确显示

### 7.2 边界测试
- 无加班记录的项目，加班时长应为 0
- 待确认的加班记录不计入统计
- 删除的加班记录不计入统计

### 7.3 变更触发测试
- 新增加班记录后，检查 `biz_project_change_detail` 表是否有对应记录（trigger_period 应为当前月份）
- 编辑加班记录后，检查变更记录表
- 确认加班记录后，检查变更记录表
- 编辑**历史月份**的加班记录，确认变更记录写入**当前月份**
