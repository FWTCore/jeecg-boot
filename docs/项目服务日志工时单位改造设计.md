# 项目服务日志工时单位改造设计

## 1. 需求背景

项目服务日志（`BizProjectScheduleLog`）当前工时字段 `workHours` 单位为**天**，但实际业务场景中用户更习惯以**小时**为单位录入工时。

同时，项目成本核算模块依赖 `workHours`（天）字段计算人力成本：
```java
// BizProjectCostDetailService.java
BigDecimal workDay = projectScheduleLogCollect.stream()
    .map(BizProjectScheduleLog::getWorkHours)
    .reduce(BigDecimal.ZERO, BigDecimal::add);
resultData.setLaborCost(workDay.multiply(perDaySalary));
```

因此需要在不影响成本核算的前提下，新增小时字段供用户录入。

---

## 2. 现状分析

### 2.1 涉及模块

| 模块 | 说明 |
|-----|------|
| 项目服务日志 | `BizProjectScheduleLog` 实体，工时单位：天 |
| 项目成本核算 | `BizProjectCostDetail` 实体，依赖 `workHours` 计算人力成本 |
| 客户服务日志 | `BizCustomerServiceLog` 实体，工时单位：天（本次不改动） |
| 工作日志 | `BizWorkLog` 实体，工时单位：天（本次不改动） |

### 2.2 数据库现状

`workHours` 字段精度：`decimal(10,1)`（1位小数）

### 2.3 精度丢失问题

如果小时转天仅保留1位小数，会导致精度丢失：

| 输入小时 | 除以8转天 | 1位小数存储 | 还原小时 | 误差 |
|---------|----------|------------|---------|------|
| 1 小时 | 0.125 天 | 0.1 天 | 0.8 小时 | **-0.2小时** |
| 3 小时 | 0.375 天 | 0.4 天 | 3.2 小时 | **+0.2小时** |
| 5 小时 | 0.625 天 | 0.6 天 | 4.8 小时 | **-0.2小时** |

**结论：1位小数无法精确存储小时转天的结果。**

---

## 3. 解决方案

### 3.1 方案设计

- 新增字段 `workHoursHour`（单位：小时），供前端录入和展示
- 保留原有字段 `workHours`（单位：天），供成本核算使用
- 后端保存时双写：`workHours = workHoursHour / 8`
- 修改 `workHours` 精度为 **3位小数**，确保小时转天不丢失精度

### 3.2 精度验证（3位小数）

| 输入小时 | 除以8转天 | 3位小数存储 | 还原小时 | 误差 |
|---------|----------|------------|---------|------|
| 1 小时 | 0.125 天 | 0.125 天 | 1.0 小时 | ✅ 0 |
| 2 小时 | 0.25 天 | 0.25 天 | 2.0 小时 | ✅ 0 |
| 3 小时 | 0.375 天 | 0.375 天 | 3.0 小时 | ✅ 0 |
| 5 小时 | 0.625 天 | 0.625 天 | 5.0 小时 | ✅ 0 |
| 7 小时 | 0.875 天 | 0.875 天 | 7.0 小时 | ✅ 0 |

**结论：3位小数可精确存储所有整数小时转天的结果。**

## 4. 数据库改动

### 4.1 修改字段精度

```sql
-- 修改 workHours 字段精度为3位小数
ALTER TABLE biz_project_schedule_log 
MODIFY COLUMN work_hours DECIMAL(10,3) COMMENT '工时(天)';
```

**说明：**
- 从 `decimal(10,1)` 改为 `decimal(10,3)`
- 历史数据自动保留，精度扩展不影响原有值
- 例如：原来存 `1.0`，修改后仍是 `1.000`

### 4.2 新增字段

```sql
-- 新增 workHoursHour 字段（单位：小时）
ALTER TABLE biz_project_schedule_log 
ADD COLUMN work_hours_hour DECIMAL(6,1) COMMENT '工时(小时)';
```

**说明：**
- `decimal(6,1)` 支持最大 9999.9 小时
- 新录入数据使用此字段

### 4.3 历史数据刷数

```sql
-- 历史数据：根据 workHours（天）反向计算 workHoursHour（小时）
UPDATE biz_project_schedule_log 
SET work_hours_hour = work_hours * 8 
WHERE work_hours IS NOT NULL AND work_hours_hour IS NULL;
```

**说明：**
- 历史数据原来以天为单位录入，乘以8转换为小时
- 例如：原来录入 `0.5` 天，刷数后 `work_hours_hour = 4.0` 小时

### 5.2 Controller add 方法改动

**文件：** `ProjectScheduleController.java`

**改动位置：** `add` 方法中，设置基本属性后、工时校验之前

**重要：双写逻辑必须在校验之前执行，否则校验时 workHours 可能为 null**

```java
// 1. 工时双写：小时转天，保留3位小数（必须在校验之前）
if (projectScheduleLog.getWorkHoursHour() != null) {
    BigDecimal workHours = projectScheduleLog.getWorkHoursHour()
        .divide(new BigDecimal("8"), 3, RoundingMode.HALF_UP);
    projectScheduleLog.setWorkHours(workHours);
}

// 2. 校验总时长（统一转换为小时计算，逻辑更清晰）
Calendar instance = Calendar.getInstance();
Date startTime = DateUtil.beginOfDay(projectScheduleLog.getCreateTime());
instance.setTime(startTime);
instance.add(Calendar.DAY_OF_MONTH, 1);
Date endTime = instance.getTime();

// 查询当日已填工时（单位：天），转换为小时统一计算
BigDecimal existWorkHoursInDay = bizWorkHoursService.getTotalWorkHours(sysUser.getId(), startTime, endTime);
BigDecimal existWorkHoursInHour = existWorkHoursInDay.multiply(new BigDecimal("8"));

// 计算总工时（单位：小时）
BigDecimal currentWorkHoursInHour = projectScheduleLog.getWorkHours().multiply(new BigDecimal("8"));
BigDecimal totalWorkHoursInHour = existWorkHoursInHour.add(currentWorkHoursInHour);

// 工时超过8小时（容忍精度误差，使用8.02作为阈值）
if (totalWorkHoursInHour.compareTo(new BigDecimal("8.02")) > 0) {
    BigDecimal remainHours = new BigDecimal("8").subtract(existWorkHoursInHour);
    throw new JeecgBootException(String.format("日期：%s 填写工时累计超过8小时，剩余【%s】小时可填",
        DateUtil.format(startTime, "yyyy-MM-dd"), remainHours.setScale(1, RoundingMode.HALF_UP)));
}
```

**注意：提示语已改为"小时"，与前端录入单位一致**

### 5.3 Controller edit 方法改动

**文件：** `ProjectScheduleController.java`

**改动位置：** `edit` 方法中，权限校验之后、工时校验之前

**重要：双写逻辑必须在校验之前执行，否则校验时 workHours 可能为 null 导致空指针异常**

```java
// 1. 工时双写：小时转天，保留3位小数（必须在校验之前执行）
if (projectScheduleLog.getWorkHoursHour() != null) {
    BigDecimal workHours = projectScheduleLog.getWorkHoursHour()
        .divide(new BigDecimal("8"), 3, RoundingMode.HALF_UP);
    projectScheduleLog.setWorkHours(workHours);
}

// 2. 校验总时长（统一转换为小时计算，逻辑更清晰）
Calendar instance = Calendar.getInstance();
Date startTime = DateUtil.beginOfDay(data.getCreateTime());
instance.setTime(startTime);
instance.add(Calendar.DAY_OF_MONTH, 1);
Date endTime = instance.getTime();

// 查询当日已填工时（单位：天），转换为小时统一计算
BigDecimal existWorkHoursInDay = bizWorkHoursService.getTotalWorkHours(data.getStaffId(), startTime, endTime);
BigDecimal existWorkHoursInHour = existWorkHoursInDay.multiply(new BigDecimal("8"));

// 计算总工时（单位：小时）
BigDecimal currentWorkHoursInHour = projectScheduleLog.getWorkHours().multiply(new BigDecimal("8"));
BigDecimal originalWorkHoursInHour = data.getWorkHours().multiply(new BigDecimal("8"));
BigDecimal totalWorkHoursInHour = existWorkHoursInHour.add(currentWorkHoursInHour).subtract(originalWorkHoursInHour);

// 工时超过8小时（容忍精度误差，使用8.02作为阈值）
if (totalWorkHoursInHour.compareTo(new BigDecimal("8.02")) > 0) {
    BigDecimal remainHours = new BigDecimal("8").subtract(existWorkHoursInHour);
    throw new JeecgBootException(String.format("日期：%s 填写工时累计超过8小时，剩余【%s】小时可填",
        DateUtil.format(startTime, "yyyy-MM-dd"), remainHours.setScale(1, RoundingMode.HALF_UP)));
}

// 3. 更新工时字段
data.setWorkHours(projectScheduleLog.getWorkHours());
data.setWorkHoursHour(projectScheduleLog.getWorkHoursHour());
```

## 7. 前端改动

### 7.1 表单改动

**改动点：**
- 表单字段由 `workHours`（天）改为 `workHoursHour`（小时）录入
- 字段标签显示为"工时(小时)"
- 提交时传递 `workHoursHour` 字段，后端自动计算 `workHours`

**示例代码：**
```vue
<a-form-item label="工时(小时)" :labelCol="labelCol" :wrapperCol="wrapperCol">
  <a-input-number v-model="model.workHoursHour" :min="0" :max="24" :precision="1" placeholder="请输入工时(小时)" />
</a-form-item>
```

### 7.2 列表改动

**改动点：**
- 列表返回数据新增 `workHoursHour` 字段
- 列表展示列由"工时(天)"改为"工时(小时)"
- 历史数据无 `workHoursHour` 时，可展示 `workHours * 8`（仅供参考）

**示例代码：**
```vue
<a-table-column title="工时(小时)" dataIndex="workHoursHour" width="100px">
  <template slot-scope="text, record">
    {{ text != null ? text : (record.workHours ? (record.workHours * 8).toFixed(1) : '-') }}
  </template>
</a-table-column>
```

### 7.3 工时校验说明

前端提交 `workHoursHour` 后，后端自动转换为 `workHours`（天）进行校验：
- 校验规则：每日工时累计不超过 8 小时
- **精度误差处理**：由于小时转天时保留3位小数会产生精度误差，校验阈值设为 **8.02小时**
  - 单次转换误差：±0.004小时
  - 理论最大累积误差：约0.06小时（按一天最多16条日志计算）
  - 实际累积误差：通常 < 0.02小时
  - 阈值选择：8.02小时，覆盖绝大部分实际场景
- 前端可增加实时校验提示：当日已填工时 + 当前输入 ≤ 8 小时

## 9. 风险评估

| 风险点 | 说明 | 应对措施 |
|-------|------|---------|
| 精度修改影响历史数据 | 精度扩展不改变原有值 | 无风险，自动兼容 |
| 成本核算失真 | 3位小数精度足够 | 无风险，计算更精确 |
| 工时校验逻辑 | 使用 BigDecimal 比较 | 无风险，精度不影响 |
| 历史数据刷数 | 天转小时可能不精确 | 历史数据本就以天录入，刷数后展示为小时仅供参考 |
| 前端兼容性 | 历史数据无 workHoursHour | 列表展示时判断，无值时显示 workHours * 8 |
